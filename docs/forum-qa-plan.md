# NanoCamp 论坛测试计划与端到端用例 · QA V2

这是测试流程模板。运行 `npm run forum:e2e:prepare` 后使用 `data/forum-e2e-guide.md`，其中账号、口令、链接及编号已填入。本模板不保存测试口令。

编制日期：2026-10-22。依据：论坛业务闭环 V3、当前实现、测试数据脚本。**人工用例全部初始为“未执行”；环境就绪检查通过不等于业务验收通过。**

## 1. 目标、范围与策略

测试目标：验证“公开发现 → 登录 → 创作交流 → 互动回访 → 举报处理及反馈”的完整闭环，重点发现越权、重复写入、输入丢失及内容状态不一致。

| 项目 | 范围 |
| --- | --- |
| 包含 | 登录/资料补全、发现、主帖/回复、关注、赞踩、收藏、消息、举报及命令行处理、默认头像、响应式、持久化 |
| 方法 | 多角色手工黑盒、正反向功能、边界值、API 权限辅助验证、异常恢复、既有自动化回归 |
| 不包含 | 网页管理页、头像上传、私信、附件、真实邮件送达、生产部署及压测、未实际使用的浏览器和真机兼容性 |
| 视觉依据 | 已批准论坛原型与现有 NanoCamp 字体、配色和组件；未提供 Figma 文件，不宣称完成 Figma 对照 |
| 发布边界 | 本地验收不代替真实邮件、部署配置、备份、生产安全及运营值守验收 |

用例优先级：P0=关键闭环/权限/数据完整性；P1=主要功能和常见异常；P2=次要体验。缺陷严重程度单独评估，不能直接等同于用例优先级。

### 2.4 边界和异常数据

| 字段 | 输入集合 | 预期 |
| --- | --- | --- |
| 标题 | 空、3、4、80、81 个 ASCII 字符 | trim 后 4–80 |
| 正文 | 空、9、10、15000、15001 个 ASCII 字符 | trim 后 10–15000 |
| 回复 | 空、全空格、1、3000、3001 个 ASCII 字符 | trim 后 1–3000 |
| 举报“其他”说明 | 0、4、5、1000、1001 个 ASCII 字符 | 至少 5、最多 1000；其他原因允许说明为空 |
| 安全输入 | `<script>alert(1)</script>`、`[测试](javascript:alert(1))`、`![测试](https://example.com/a.png)` | 不执行脚本、危险链接或加载远程图片 |
| 错误密码 | `Wrong-Password-Only-Once!` | 登录失败，不建立会话 |

PowerShell 示例：`('a' * 80) | Set-Clipboard`，修改长度即可准备输入。前端 maxlength 阻止超长输入属于正确限制；必须另测绕过前端后的服务端拒绝。成功发布边界数据会消耗额度，应使用独立轮次。

## 3. 进入、退出标准及时间安排

**进入条件：** 服务及数据库可用；六角色存在；环境检查通过；角色会话隔离；已记录版本、批次和数据初始状态。条件不满足时记录环境阻塞，不把未执行用例记为业务失败。

**退出条件：** 所有 P0/P1 已执行；P0 全部通过；无未关闭 Critical/High 缺陷；P1 全通过或逐项由负责人接受延期并记录影响；失败和阻塞均有证据/缺陷。不能只凭总通过率签发上线结论。

| 阶段 | 估算人工时间 | 产出 |
| --- | --- | --- |
| 环境及数据核对 | 10–15 分钟 | 版本、账号、数据记录 |
| 冒烟 | 20–30 分钟 | 核心路径结论 |
| 功能、权限及数据回归 | 2–3 小时 | 逐用例结果、缺陷 |
| UI、异常及复测 | 45–60 分钟 | 截图、异常证据、复测结果 |

时间仅为计划估算；边界与限流隔离轮次另计。

## 5. 手工测试用例

每例提供优先级、类型、前置、步骤与逐步预期、后置。状态/实际结果/证据统一填写第 8 节台账，初始均为“未执行”。**每步均满足才可标通过**；部分步骤未做时说明阻塞或未覆盖，不把 API 验证当作 UI 验证。

### TC-001 公开发现、分类、搜索和排序

**P1｜功能/UI｜前置：** 访客；六个测试帖公开。

1. 打开论坛，检查左侧发布按钮、我的帖子/回复/关注/收藏，并切换搜索框下方的三个横向分类。**预期：** 布局与导航正确；列表展示作者、较大标题、摘要及点赞/收藏/回复数量；个人内容页高亮对应入口。
2. 搜索 `{{RUN}}`，切换最近回复/最新发布后刷新。**预期：** 分类、关键词、排序写入 URL 且保留，结果符合条件；同秒预置数据不强行比较次序。
3. 搜索 `not-found-{{RUN}}`。**预期：** 正常空状态，无无关结果或异常页。

**后置：** 清空搜索，无数据写入。排序的有效变化在产生新回复后再次核对。

### TC-002 访客可读、互动需登录

**P0｜权限｜前置：** 独立访客窗口。

1. 打开 D01 和作者公开主页。**预期：** 可读公开正文及资料，没有邮箱、私有收藏/举报/消息。
2. 点击发起讨论、关注或收藏。**预期：** 引导登录，不能先产生互动。
3. 直达 `/forum/me/`、`/forum/notifications/`。**预期：** 跳转登录且保留站内目标。

**后置：** 保持匿名，回跳测试使用 TC-003。

### TC-003 密码登录、失败和回跳

**P0｜功能｜前置：** 作者账号；由 `/forum/new/` 转来的登录页。

1. 输入作者邮箱及错误密码一次。**预期：** 失败提示，不产生登录态。
2. 改为正确口令登录。**预期：** 返回发起讨论页，不自动发帖。
3. 刷新后点击右上角头像，再从侧栏进入“我的资料”，修改一句话介绍并保存、刷新。**预期：** 头像直接打开 `/forum/notifications/`，资料在同一套个人中心布局中原地保存并持久化；头像旁不再有独立信封入口。

**后置：** A 登录作者；不要反复试错触发认证限流。

### TC-004 退出与账号切换

**P0｜权限｜前置：** 作者已登录。

1. 在个人中心退出。**预期：** 右上角变为登录入口。
2. 直达并刷新个人参与/消息页。**预期：** 要求登录，新请求不展示原用户私有数据。
3. 登录参与者。**预期：** 私有内容属于参与者，不串号。

**后置：** A 重新登录作者，B 维持参与者；浏览器历史静态画面不作为服务端泄露证据。

### TC-005 验证码注册、失败与一次性消费

**P1｜集成｜前置：** 新邮箱 `e2e-signup-{{RUN}}@example.test` 未注册；日志终端打开。

1. 请求验证码，读取匹配邮箱的最新日志。**预期：** 有发送结果和验证码日志，不承诺实际投递邮件。
2. 先提交一次错误码，再提交正确码。**预期：** 错误码不能登录；正确码进入资料补全。
3. 补全昵称/密码后退出，用新密码登录；另在新独立会话重用已消费验证码。**预期：** 密码可登录，旧验证码不能再消费。

**后置：** 新注册账号留存，六个预置角色不变。

### TC-006 资料不完整时的参与门槛

**P0｜权限｜前置：** 待完善账号尚未填昵称。

1. 登录该账号并访问发帖页。**预期：** 转资料补全，保留目标。
2. 留空昵称保存。**预期：** 必填校验阻止提交。
3. 设置 `端测补全伙伴` 并保存。**预期：** 能继续发帖流程，资料刷新后仍在。

**后置：** 账号不再缺资料，复测需新批次。

### TC-007 发布及回访

**P0｜功能｜前置：** 作者有额度，N01 尚未发布。

1. 填 N01，预览并发布。**预期：** 进入详情，标题、正文、分类、作者正确。
2. 刷新并搜索标题。**预期：** 内容仍在、搜索可回访。
3. 从我的帖子回访并记实际 URL。**预期：** 归属作者；详情右侧是作者信息，无重复发起讨论入口。

**后置：** 保留 N01 给安全/编辑验证。

### TC-008 输入长度与空白边界

**P1｜边界/API｜前置：** 独立轮次或有充分额度；2.4 输入已准备。

1. 逐组验证标题及正文边界。**预期：** 非法值不能发布；合法上下界可提交；前端允许以 maxlength 限制超长输入。
2. 逐组验证空回复、全空格及 1/3000/3001 字符回复。**预期：** trim 后合法值成功，空或超限不创建回复。
3. 用 6.2 helper 直接提交标题 81/正文 15001。**预期：** 422 `invalid_content`，不能绕过前端落库。

**后置：** 记录每个变体结果和新增内容；未测完不能把整例标通过。

### TC-009 草稿恢复、隔离和清除

**P1｜功能/隐私｜前置：** 作者/参与者；未发布的新建草稿。

1. 作者输入 `draft-{{RUN}}` 等内容，出现保存提示后刷新。**预期：** 同账号恢复标题、分类、正文。
2. 退出并切参与者打开新建页。**预期：** 不恢复作者草稿。
3. 切回作者恢复草稿，发布成功后再开新建页。**预期：** 不恢复已发布草稿。

**后置：** 增加一个测试帖；草稿是当前浏览器按账号隔离的本地数据，最多保留 7 天，不要求跨设备同步。

### TC-010 发布前 Markdown 预览与发布后展示

**P1｜功能/UI｜前置：** 作者有额度，打开新建讨论；不要编辑已发布帖子。

1. 输入二级标题、列表、代码块和普通 https 链接，切预览再返回。**预期：** 格式合理，草稿输入未丢。
2. 确认内容后发布并刷新详情。**预期：** 最终结构与预览一致，代码按文本显示；发布后不能修改。
3. 在手机宽度查看长代码/表格。**预期：** 内容区域内滚动，不撑破整页。

**后置：** 记录新帖 ID；修改需求通过撤回再重新发布处理，不做发布后编辑。

### TC-011 作者不能修改已发布主帖

**P0｜权限/数据｜前置：** 作者打开 D02；记录当前标题、正文、分类和版本。

1. 查看帖子操作栏及页面内容。**预期：** 作者直接看到撤回按钮，无编辑、修改标题或修改分类入口。
2. 直接访问 D02 的 edit 地址。**预期：** 404，不显示编辑表单。
3. 使用 6.2 helper 向主题接口 PATCH 新标题、正文、分类。**预期：** 405 method_not_allowed；刷新后原内容与版本不变。

**后置：** D02 未修改，供并发拒绝验证。

### TC-012 并发修改请求同样被拒绝

**P0｜并发/数据｜前置：** 作者；两个独立页面记录 D02 当前内容；helper 已定义。

1. 两个页面分别构造不同正文的 PATCH 请求。**预期：** 两个请求均为 405，不因用户是作者而开放编辑。
2. 刷新 D02 并查询主题 API。**预期：** 标题、正文、分类和版本均与前置记录一致。
3. 从搜索和我的帖子回访 D02。**预期：** 没有修改或新增副本，也没有编辑入口。

**后置：** 内容不变；不再测试“编辑成功后的版本冲突”。

### TC-013 撤回主帖与上下文

**P0｜数据｜前置：** 参与者先给 D03 回复 `撤回测试：保留这条已有回复。`。

1. 作者撤回 D03 并确认。**预期：** 撤回占位，已有回复仍在。
2. 访客搜索及直达原帖。**预期：** 搜索不公开撤回正文；直达保留上下文，不泄漏原正文。
3. 尝试新增回复。**预期：** 不能成功，已有回复不丢。

**后置：** D03 已撤回，不再用于初始公开页自检。

### TC-014 回复主帖与指定对象

**P0｜功能｜前置：** A 作者、B 参与者；D01 公开。

1. B 在正文下方、评论列表上方的输入框发布 C01 并刷新。**预期：** C01 在本人视角排第一，计数加 1，归属参与者；记下 ID。仅直接回复主帖的本人评论优先，定向回复不置顶；超过 30 条历史评论时首批仍最多加载 30 条，其他账号不会因 B 发布评论而把该评论置顶。
2. A 点击 C01 的回复，输入 `可以，我们先确定第一版的数据字段。`，切换到另一条再切回，取消后重新打开并发布。**预期：** 输入框在所选评论下方展开，不跳到列表底部；切换和取消保留草稿；发布期间不能切换目标。目标正确，新楼层可跳转原对象。
3. 双方在我的回复和消息中回访。**预期：** 归属和消息对象正确，跳转对应楼层。

**后置：** C01 给 015/016；R01 保持不变。

### 6.2 API 辅助

在已登录本地网站的浏览器 Console 定义。使用当前账号，不会自动切角色；POST/PATCH 会产生业务操作，只用于测试数据。

```javascript
var e2eApi = async (path, body, method = 'POST', key = crypto.randomUUID()) => {
  var s = await (await fetch('/api/session', {cache:'no-store'})).json();
  var r = await fetch(path, {
    method,
    headers: {'Content-Type':'application/json','x-nc-csrf':s.csrf,'Idempotency-Key':key},
    body: JSON.stringify(body)
  });
  return {status:r.status, body:await r.json()};
};
// TC-034：作者有额度时运行
var e2eKey = crypto.randomUUID();
var e2ePayload = {title:'[幂等 {{RUN}}] 重复提交检查',category:'questions',body:'这是用于检查重复提交和幂等键冲突的测试正文。'};
await e2eApi('/api/forum/topics',e2ePayload,'POST',e2eKey);
await e2eApi('/api/forum/topics',e2ePayload,'POST',e2eKey); // 同一 ID
await e2eApi('/api/forum/topics',{...e2ePayload,body:'改变后的正文仍然满足最少字数。'},'POST',e2eKey); // 409
```

接口参考：已读为 `POST /api/forum/notifications/read`，体 `{ids:[消息ID]}`；禁止修改验证为 `PATCH /api/forum/topics/帖子ID`，体 `{title,category,body,version}`，预期 405；撤回为 `POST /api/forum/topics/帖子ID/withdraw`，体 `{}`。详情 `GET /api/forum/topics/帖子ID` 返回当前版本。TC-033 无 CSRF 的请求直接用 fetch，不使用会自动带令牌的 helper。

## 7. 风险和缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| Cookie 共用 | 假多角色、身份串用 | 独立配置文件，每步核对昵称 |
| 状态被用例改变 | 复测误判、冷却阻塞 | 记录依赖和后置；用新轮，不清库 |
| 额度消耗 | 合法操作被误判失败 | 发帖 3/小时、回复 20/小时、举报 10/小时；重度变体独立轮次 |
| console 发信 | 无法证明真实邮件送达 | 生产前另验真实邮箱 |
| UI 禁用代替权限验证 | 漏掉越权 | 刷新、跨会话回访、反向 API |
| 隐藏恢复消息原因错乱 | 用户收到错误回执 | 对照旧/新原因及正文可见性 |
| 草稿是本机存储 | 清缓存丢失、不能跨设备 | 记录本地存储约束，失败保留输入并可复制 |
| 没有网页管理页 | 举报无人处理 | 验收命令行真实处理能力，上线前指定值守人员 |

