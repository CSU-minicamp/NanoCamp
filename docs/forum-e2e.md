## 测试流程（按顺序执行）

### 01 访客浏览与登录回跳

1. 未登录访问论坛，切换提问交流、作品实践、组队招募，搜索当前批次标记 `{{RUN}}`。
2. 打开主帖、作者主页；应能看到正文及默认头像，不显示邮箱、举报记录等私有信息。
3. 点击发起讨论、关注或收藏，应进入登录流程；直接访问 `/forum/me/`、`/forum/notifications/` 应要求登录。
4. 输入错误密码一次，确认不能登录；随后用正确的作者账号登录，应回到目标页面，右上角显示作者登录状态并能进入个人中心。
5. 登录“待完善”账号，打开“发起讨论”：应进入昵称补全页。填写昵称保存后继续；此操作会改变该账号的初始状态。

### 02 发帖、草稿和 Markdown

作者在“发起讨论”填写：

```text
标题：[手工E2E] 我想做一个校园活动提醒工具
分类：作品实践
正文：
## 第一版计划
做一个整理校园活动信息的小工具，先验证浏览和提醒流程。

- 展示近期活动
- 记录感兴趣的活动

欢迎一起讨论功能范围。
```

1. 输入一部分后刷新，确认同一账号、同一浏览器恢复草稿；退出后切换参与者，不能恢复作者草稿。
2. 切换预览，检查标题和列表排版；返回写作，输入不丢失。
3. 标题不足 4 字、正文不足 10 字时不能成功发布；改为上面的完整数据再发布。
4. 发布后进入详情、列表可搜索、刷新后仍在，“我的帖子”包含新帖；成功发布后再次打开新建页不应恢复已发布草稿。
5. 双击发布按钮不应创建重复帖子。帖子详情右侧是作者信息，不应出现另一个“发起讨论”入口。

### 03 赞、踩、收藏、关注

使用参与者对[交流主帖]({{MAIN}})操作，作者在独立窗口核对：

| 操作 | 预期 |
| --- | --- |
| 点赞 | 赞 1、踩 0；刷新后仍选中 |
| 改为踩 | 赞 0、踩 1，赞踩不能同时选中 |
| 再点踩 | 赞 0、踩 0 |
| 再点赞 | 赞 1、踩 0；作者消息不因取消再赞而不断新增 |
| 收藏、刷新、进入我的收藏 | 能找到主帖；取消后移出收藏 |
| 关注作者 | 关注列表、作者粉丝列表及关注动态中可见 |
| 取消关注 | 从关系列表移除；关注动态不再含该作者帖子 |

最后保持“点赞、关注、收藏”开启，供后续回访核对。作者不能给自己的帖子或回复投票，不能关注自己。

### 04 回复、引用、编辑与版本冲突

1. 参与者在主帖回复：`我可以负责前端，建议先把活动列表做出来。`，提交后定位到该楼层；刷新和“我的回复”均可找到。
2. 作者点击这条回复的“回复”，输入：`可以，我们先确定第一版的数据字段。`，应显示回复对象，并定位到正确楼层。作者收到参与者回复消息，参与者收到作者定向回复消息。
3. 参与者编辑自己刚发布的回复为：`我可以负责前端，第一版先实现活动列表和详情。`，保存后正文及“已编辑”标识更新；作者不能编辑参与者回复。
4. 作者在两个标签页打开[编辑测试帖]({{EDIT}})的编辑页。第一页保存标题和正文，第二页用旧版本保存：应提示版本冲突，第二页输入不丢失，不能覆盖第一页的新内容。
5. 打开[分页帖]({{PAGES}})第二页，仅显示第 31 楼。访问 `/forum/replies/{{LAST_REPLY}}/` 应跳到第二页正确楼层。

### 05 消息与私有数据

1. 作者进入消息中心，核对回复、赞和关注消息，分类筛选可用；进入消息详情后对应消息已读。
2. 点击全部标为已读，刷新后未读数应为 0，右上角未读标记消失（允许页面刷新或最长约 60 秒更新）。
3. 参与者消息中心只能显示自己的消息，不能看到作者收到的关注和赞；“我的举报”也只能看到自己提交的记录。
4. 退出登录，再直接访问个人参与、收藏、消息页面，应要求重新登录。

### 06 举报成立 → 隐藏 → 回执 → 恢复

1. 举报人打开主帖，举报预置的 **回复 {{REPORT_REPLY}}**（正文包含“专门用于举报成立”）。原因选择“其他”，补充：`端到端验收：核对隐藏和恢复流程，不代表真实违规。`
2. 在“我的举报”记录本次编号 `R`。再次提交相同内容的举报，应复用未结案记录，不产生重复待处理单。
3. 在项目目录的 PowerShell 执行：

```powershell
npm run forum:moderate -- actor={{OPERATOR}}
# 查看结果找到刚才的举报编号；将下面这一行的 0 替换为该编号
$reportId = 0
npm run forum:moderate -- actor={{OPERATOR}} report=$reportId
npm run forum:moderate -- actor={{OPERATOR}} report=$reportId version=1 action=claim reason="E2E核实处理中"
npm run forum:moderate -- actor={{OPERATOR}} report=$reportId version=2 action=uphold reason="E2E测试隐藏，不代表真实违规"
```

4. 刷新主帖，回复内容变为隐藏占位、正文不可读，已发布回复计数减 1。举报人收到处理结果，回复作者收到内容状态通知，普通作者不能看到举报人身份。
5. 领取后的举报不能由举报人撤回；重复使用旧版本处理应报版本冲突，不能覆盖结果。
6. 恢复：

```powershell
npm run forum:moderate -- actor={{OPERATOR}} report=$reportId version=3 action=restore reason="E2E核对完成，恢复回复"
```

回复正文和计数恢复；举报人及内容作者收到相应通知，之前的处理通知保留当时的原因。

### 07 举报驳回与撤回

1. 举报人举报[驳回测试帖]({{DISMISS}})，记录新编号。使用处理人员执行 `action=dismiss version=1 reason="E2E核对后未发现问题"`，无需先领取；帖子保持公开，举报人收到驳回结果。
2. 举报人举报[举报撤回测试帖]({{CANCEL}})，在处理人员领取前点击“撤回举报”，应变成已撤回，退出待处理队列。
3. 普通作者用命令行 `actor={{AUTHOR}}` 查询队列应被拒绝。网站不存在面向公众的举报处理页面。

### 08 撤回、权限、安全与手机

1. 参与者给[撤回测试帖]({{WITHDRAW}})增加回复，作者再撤回主帖：列表不再公开展示正文，直达原帖显示作者已撤回，已有回复仍保留，不能继续回复。
2. “禁言账号”能登录、浏览，但尝试点赞、关注、发帖或回复均被拒绝；消息仍能阅读、标为已读。网页目前没有禁言管理入口。
3. 作者在手工测试帖正文加入 `<script>alert(1)</script>` 及 `[测试](javascript:alert(1))`，预览和保存后不得弹窗或出现可执行危险链接。
4. 在 360px 和常规桌面宽度检查列表、详情、作者主页、个人参与、编辑器、消息和举报弹窗；头像清晰、无横向溢出，弹窗可取消及按 Escape 关闭。
5. 停止再启动本地应用后，已发布帖子、回复、关系、收藏和已读状态仍在。不要通过清空数据库验证重启。

## 验证码与测试边界

环境检查命令为 `npm run forum:e2e:verify`，会验证六个账号的 HTTP 登录、私有页面、资料补全跳转、禁言限制、预置页面及分页，不提交帖子或互动。结果写入 `data/forum-e2e-readiness.json`。该命令针对初始数据，手工修改账号资料或撤回测试帖子后应先生成新批次再检查。

当前邮件是 `console` 模式，不会发真实邮件。需要测验证码注册时，用全新 `e2e-signup-任意后缀@example.test` 请求验证码，在独立终端查看：

```powershell
Get-Content -LiteralPath ./data/local-server.log -Tail 50 -Wait
```

以日志中匹配邮箱的最新验证码登录，完成昵称和密码补全；重复验证码、错误码不应成功。此方法只能证明本地发码逻辑，不能证明真实邮箱投递。邮件送达、生产域名、反向代理及公网部署不在本地验收结果中。

发帖每账号每小时 3 条、回复每小时 20 条、举报每小时 10 条；刚结案或撤回的同一内容同一举报人有 24 小时间隔。不要重复点击冲击限流后误判业务失败。要重新执行完整测试，使用新批次：

```powershell
node scripts/forum-e2e-prepare.mjs --new-run
```

旧数据保留，新账号和帖子与旧批次隔离。默认不带参数执行会保留当前批次，不重置密码、帖子或测试进度。账号密码仅保存在被 Git 忽略的 `data/` 中，请勿提交这些文件。
