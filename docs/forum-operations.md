# 论坛运行与举报处理

论坛复用现有邮箱登录、会话及 MySQL 配置，没有独立管理页面。入口为 `/forum/`，个人参与记录为 `/forum/me/`，消息为 `/forum/messages/`，旧 `/forum/notifications/` 自动跳转。

帖子图片已开放，升级时重新执行 `npm run forum:migrate` 增加图片表；图片暂存 MySQL，部署后安排过期草稿清理。存储和迁移细节见 [帖子图片说明](forum-images.md)。

论坛侧栏集中放置“发起讨论”“我的帖子”“我的回复”“消息”“我的关注”“我的收藏”，个人内容通过 `/forum/?view=topics|replies|following|bookmarks` 访问，需要登录。原 `/forum/me/?tab=...` 四个地址保留重定向，并传递续载批次参数。个人中心保留资料、粉丝、举报及安全设置；消息独立到论坛侧栏，包含私信与原通知，见 [私信运行说明](private-messages.md)。

主栏顶部提供搜索及横向讨论分类，分类、关键词和排序可组合筛选。搜索与分类仅在“全部讨论”中显示，四个个人内容页只展示对应标题和内容。帖子列表采用作者、标题、两行摘要、互动栏的布局；点赞和收藏展示真实聚合数量及当前账号状态，可直接操作，取消收藏后从我的收藏中移除。统计以列表批次为单位聚合查询，避免逐条查询。

帖子列表、作者主页中的帖子、个人帖子/回复/收藏列表，以及帖内评论采用滚动续载，页面不显示翻页控件。内部仍按每批 20 个帖子、30 条评论读取，避免首屏一次加载全部内容；`fragment=1` 请求复用原页面的会话及可见性检查，并返回不缓存的 HTML 片段。失败后保留已加载内容，提供重试。

本人直接回复主帖的已发布评论优先，最新一条排在最前；其他评论按楼层顺序加载。回复具体楼层的评论不置顶。已加载的定向回复归入对应讨论，保持一层缩进，并用被回复对象、楼层和摘要标明直接关系；父回复不在当前批次时可通过引用跳转。

每次最多读取 30 条正文。本人评论使用 `idx_replies_own(topic_id,author_id,status,sequence)` 索引分批读取，其他评论用原楼层索引续载，不读取全部正文后再排序。直接评论发布后显示在本人首批最前，定向回复仍归入对应讨论；引用、消息与我的回复链接通过 `?reply=评论ID` 计算当前查看者的目标批次，只读取该批。旧 `page + hash` 链接在必要时由前端转到新的定位地址，不再累计加载前面所有批次。

评论内回复使用统一缩进，避免深层回复在手机上越来越窄；原内容撤回或隐藏后不显示摘要。升级时执行 `npm run forum:migrate` 为已有数据库补充本人评论索引。

作者的帖子和评论操作栏直接显示“撤回”按钮，点击后仍需确认；其他用户的举报保留在更多菜单中。主帖评论框位于正文下方、评论列表之前；点击评论的“回复”时，同一个输入框移到该评论下方，切换对象或取消不会清空草稿，也不会滚动到列表底部。发布期间禁止切换回复对象，避免正文与目标不一致。

## 初始化

先在 `data/config.json` 配置数据库、认证密钥和邮件服务。公开运营必须配置实际发信服务，`console` 只适合本地测试。配置和数据库备份不进入版本库。

```powershell
npm ci
npm run db:migrate
npm run forum:migrate
npm start
```

论坛迁移可重复执行；迁移账号需要建表权限，运行账号只需业务数据权限。先备份已有数据库，再在目标环境执行迁移。新环境不会自动生成讨论、运营账号或管理员。

## 举报处理（服务器命令行）

仅持有服务器和数据库访问权限的运营人员执行。所有命令使用当前目录的数据库配置，操作前确认目标环境。下面的 `19`、`4` 是参数示例，请替换为实际用户和举报编号。

首次指定一个已注册用户作为维护者；已有维护者后，此入口自动拒绝重复初始化：

```powershell
npm run forum:moderate -- bootstrap=19
```

查看队列及单条举报（包括内容、当前版本）：

```powershell
npm run forum:moderate -- actor=19
npm run forum:moderate -- actor=19 report=4
```

领取后处理，参数 `version` 必须使用最新查询结果；每次成功操作都会增加版本号，防止多人相互覆盖：

```powershell
npm run forum:moderate -- actor=19 report=4 version=1 action=claim reason="开始核实"
npm run forum:moderate -- actor=19 report=4 version=2 action=uphold reason="核实违反社区规则，隐藏内容"
```

举报不成立时使用 `action=dismiss` 并填写具体原因。误隐藏需要恢复时，对已成立举报使用 `action=restore` 和最新版本。处理结果发送给举报人，隐藏、恢复状态发送给内容作者；公开页面不展示举报人信息。处理与恢复记录保留在 `forum_audit`。帖子和评论发布后不能修改；`forum_revisions` 只保留既有历史记录，不再通过发布后编辑写入。

当前没有网页禁言入口；成员状态保存在 `forum_members`，受限用户仍可查看自己的消息和举报结果。公开运营需安排人员定期检查命令行举报队列，此版本没有邮件或后台推送提醒运营人员。

## 检查

```powershell
npm run check
npm test
```

论坛集成测试连接配置中的 MySQL，使用独立标识的测试用户和内容并在结束后清理；在专用测试数据库执行，不要指向生产库。测试覆盖重复提交、赞踩切换、关注、收藏、版本冲突、举报、权限隔离和内容隐藏恢复。页面使用服务端渲染，个性化内容不进入共享缓存。

## 回复展示与搜索

回复每批最多 30 条；本人直接回复主帖的已发布评论优先且按最新排序，定向回复不置顶，其余按楼层顺序加载。已加载的回复归入被回复的讨论，采用一层缩进；回复摘要与楼层链接标明直接回复对象，父回复不在当前批次时可通过引用跳转。

论坛主内容区搜索框默认显示“论坛内搜索”，提交至 `/forum/?q=关键词`，输入时从公开帖子查询匹配结果，最多显示 10 条，单行展示标题并高亮匹配文字。支持上下键选择、回车打开帖子、Escape 收起，以及中文输入法组合输入；未选择候选项时回车展示搜索结果列表。右上角导航搜索在所有页面均为全站搜索，提交至 `/search/`。
