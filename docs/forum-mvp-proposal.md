# NanoCamp 论坛最小公开运营版方案

> 已被 [论坛业务闭环方案](forum-business-plan.md) 取代。本文为旧版收缩方案，不再作为实施依据；其中对关注、投票、举报和消息的后置安排已取消。

日期：2026-10-22。状态：方案与视觉原型，尚未实施。
本方案取代 `forum-proposal.md` 中较大的首期范围：不制作管理页，不将消息、点赞、收藏、标签体系、答案采纳或招募状态作为本期依赖。

## 1. 唯一目标

完成“公开发现话题 → 登录发帖 → 他人回复 → 作者从我的参与再次进入讨论”的业务闭环。新增 `/forum/`，使用现有账号、会话、个人中心和网站视觉。

闭环验收以两名真实测试账号互相发帖和回复、数据刷新/重启后保留为准，不以页面数量或静态效果为准。

## 2. 参考与设计

- [GitHub Community Discussions](https://github.com/orgs/community/discussions)：借鉴分区导航、标题列表、明确发布入口。
- [GitHub 发布与回复流程](https://docs.github.com/en/discussions/collaborating-with-your-community-using-discussions/participating-in-a-discussion)：借鉴分类、正文编辑与预览、讨论内回复。
- [CSDN](https://www.csdn.net/)：借鉴内容标题、简短摘要、作者与时间的信息层次；不引入广告、商业推荐和复杂运营侧栏。

以上是参考观察。以下范围和交互是 NanoCamp 自己的建议，不是参考网站功能的完整复刻。

延续现有浅紫背景、蓝绿强调、NanoDisplay 无衬线标题、全站导航及右上角个人中心。论坛采用稳定的阅读布局，桌面清楚分栏，手机端单列。动效限定为切换、菜单与提交反馈，并遵循减少动态效果设置。

原型图中账号、头像、帖子和回复数字均为示意数据。实现时复用真实 Logo；首期使用现有默认头像或昵称首字，不包含头像上传。原型顶部搜索统一沿用现有“站内搜索”，不承诺用户名搜索；列表内“搜索话题”仅搜索论坛。

## 3. 本期功能边界

| 本期必须完成 | 行为 |
| --- | --- |
| 公开浏览 | 游客可以看列表、分区、帖子和回复 |
| 分类与排序 | 提问交流、作品实践、组队招募；默认最近回复，可切换最新发布 |
| 论坛搜索 | 按标题和正文关键词搜索，保留分类与分页条件 |
| 登录衔接 | 未登录发帖/回复进入现有登录页，补全资料后回到原来的操作位置 |
| 发帖 | 标题、一个分类、Markdown 正文、预览、发布 |
| 回复 | 在帖子底部回复，可指定被回复的楼层，显示上下文入口；不做无限嵌套 |
| 编辑/撤回 | 用户可编辑和撤回自己的内容，保存编辑版本，避免并发覆盖 |
| 我的参与 | 我的主题、我回复过的主题；从个人中心或论坛侧栏进入 |
| 草稿恢复 | 当前浏览器保存，按用户隔离，发布成功后清除，退出时清理 |
| 基础写入约束 | 服务端鉴权、CSRF、长度限制、限流、幂等与安全渲染 |

明确后置：管理页、消息中心、未读提醒、点赞、收藏、采纳答案、结束招募、标签管理、图片与附件上传、私信、邮件通知、积分等级、推荐算法。右侧不放依赖这些能力的入口。

没有管理页不等于任何用户都能操作他人内容。保留内容可见状态和站内运营联系渠道；必要的下架通过受控维护脚本执行并记录操作，不向用户提供管理菜单。若公开运营实际需要多人审核，再单独设计管理模块。没有站内举报工单，也不展示无法履约的举报按钮。

## 4. 页面方案

### A. 论坛首页 `/forum/`

- 标题“社区论坛”，右侧“发起讨论”。不用占屏的大海报。
- 左侧：全部讨论、提问交流、作品实践、组队招募、我的参与。
- 主栏顶部：最近回复/最新发布，论坛搜索框。
- 列表行：默认头像、标题、一行摘要、作者、分区、时间、公开回复数。
- 每页 20 条，明确上一页/下一页；条件写入 URL，返回列表恢复筛选和页码。
- 手机端分类改横向菜单，主题信息保持单列，不缩成多栏。
- 首期不设“热门”和浏览量，不展示空的排行榜或虚假统计。

### B. 话题详情 `/forum/topics/:id/`

- 顶部面包屑、标题、作者与时间；作者看到自己的编辑/撤回入口。
- 主帖正文 → 回复列表 → 回复编辑框，右侧仅保留分类和返回列表/发起讨论入口。
- 回复按时间升序，每页 30 条，发布成功定位至新增回复。
- 回复链接带稳定定位信息；有分页时服务端确定所在页，不能只使用当前页找不到的锚点。
- 用户点击“回复某人”时，在编辑框显示引用对象，可取消；正文依然平铺阅读。
- 未登录编辑区显示登录入口，回跳保留话题、回复对象和回复位置。
- 编辑器含写作/预览和提交反馈；失败保留输入，不生成假回复。

### C. 发起/编辑讨论 `/forum/new/`、`/forum/topics/:id/edit/`

- 标题、分类、正文编辑区、写作/预览、取消与发布。
- 自动保存状态只在保存实际成功后出现；明确草稿仅在当前浏览器。
- Markdown 支持列表、引用、代码块、普通链接；不开放 HTML、远程图片和自动链接抓取。
- 发布成功直接进入话题详情；重复点击按钮或网络重试只创建一条话题。
- 编辑复用同一页面，显示“保存修改”，携带预期版本；冲突时保留本地文本。

### D. 我的参与 `/forum/me/`

- 复用论坛列表布局，不新增一套独立视觉；仅“我的主题”和“我的回复”两个页签。
- 我的主题展示自己创建的主题和撤回状态；我的回复按自己最近回复的时间排列关联主题，同一主题去重。
- 点击直接定位自己最近的公开回复；目标被隐藏时不泄露原文。
- 个人中心增加“我的论坛参与”入口；右上角个人入口继续进入现有个人中心。
- 本期没有未读数和消息中心，用户通过时间与回复数判断进展。

## 5. 最小用户流程

1. 游客从导航进入论坛，搜索或按分类找到帖子，打开阅读全文。
2. 点击发起讨论或回复，若未登录，进入已有登录页并携带站内 `next`。
3. 登录后先完成现有资料要求，再回到发布页或原话题；不能丢失目标地址。
4. 提交内容，服务端校验身份和输入，事务落库，返回最终内容 ID。
5. 页面显示新主题/回复；另一账号刷新即可看到并回复。
6. 作者从我的参与返回讨论，继续回复或编辑自己的内容。

闭环里不依赖邮件、实时推送、管理员审核或第三方论坛账号。

## 6. 内容与权限规则

- 分类固定三个，首期从配置或种子数据初始化，不制作分类管理页。
- 普通用户只能编辑/撤回自己的内容，不能改所属作者或他人内容。
- 标题建议 4—80 字；主帖 10—15,000 字；回复 1—3,000 字；字符与请求字节分别限制，保持现有 64KB 请求上限。
- 无回复的主题可撤回；有回复时撤回自己的正文并留下占位，其他人的回复保留。
- 回复撤回显示占位，引用关系保留；不把已撤回内容原文放在列表摘要或接口中。
- 撤回主题后停止新增回复；编辑不顶帖，公开新回复才更新活动时间。
- 帖子/回复版本号支持并发冲突判断，超时重试用用户+操作+幂等键去重。
- 登录失效不清空正在编辑的文字；重新登录后回原位置，由用户确认是否继续提交。
- 具体限流作为配置，建议初始每小时 3 个主题、20 条回复，真实使用后调整。

## 7. 现有体系下的最小实现

沿用当前 Node 原生 HTTP、MySQL、`users`、`sessions`、CSRF 和现有个人资料检查。新增论坛业务与页面文件，不迁移框架、不再做第二套登录。

最小数据：

| 数据 | 用途 |
| --- | --- |
| `forum_topics` | 作者、分类、标题、Markdown/纯文本、公开/撤回/隐藏状态、版本号、回复数、活动时间 |
| `forum_replies` | 主题、作者、目标回复、正文、状态、版本和稳定顺序 |
| `forum_write_requests` | 记录幂等键及操作结果，重复发布返回原结果 |
| `forum_revisions` | 编辑历史，避免不可追溯覆盖；不向普通游客开放历史正文 |
| `schema_migrations` | 跟踪数据库版本，升级已有库不能只靠 CREATE TABLE IF NOT EXISTS |

分类使用固定 slug，暂不增加标签、点赞、收藏、消息、举报表。必要的运营下架脚本写本地追加式操作日志；它不是网页管理模块。

论坛读请求进入请求期渲染，不能使用现有 `renderOnce` 永久缓存。私有“我的参与”不共享缓存。写入采用同一连接事务；创建回复、公开计数、活动时间和幂等结果一起提交。

论坛搜索独立查数据库，不注入现有站点静态索引。首期小规模使用参数化 LIKE 并转义通配符，限制搜索长度、频率和分页深度；中文规模增长后再调整检索方式。

最小 API：

- `GET /api/forum/topics`：列表、分类、搜索、排序和分页。
- `GET /api/forum/topics/:id`：主帖和当前页回复。
- `POST /api/forum/topics`：创建主题。
- `PATCH /api/forum/topics/:id`：作者编辑。
- `POST /api/forum/topics/:id/replies`：发布回复。
- `PATCH /api/forum/replies/:id`：作者编辑回复。
- `POST /api/forum/topics/:id/withdraw`、`POST /api/forum/replies/:id/withdraw`：本人撤回。
- `GET /api/forum/me`：当前用户主题和回复过的讨论。

所有写操作服务端检查会话、资料状态、CSRF、目标可见性与所有权；隐藏内容在详情、列表、搜索、我的参与中使用一致规则。Markdown 解析与清洗使用经过评估的库，禁止原始 HTML 和危险链接。

## 8. 实施顺序与完成标准

一次公开版本，按依赖分三步实现，不把后面的步骤伪称已完成：

1. 数据迁移与查询、论坛列表/详情、分类、搜索和分页。
2. 登录回跳、发布、回复、安全渲染、编辑撤回、幂等与事务。
3. 我的参与、草稿、手机适配、错误恢复及端到端验收。

必须通过：两账号发帖回复并在我的参与找到记录；重启服务后内容存在；登录回跳不丢位置；游客/其他账号不能修改帖子；重复发布不重复写入；撤回不破坏他人回复；搜索结果只含公开内容；数据库错误明确提示而非空列表；XSS 输入安全显示；手机端输入和键盘操作无障碍。

## 9. 原型说明

三张视觉图分别为首页、详情页和发布页；“我的参与”复用首页列表，仅切换两个个人页签。原型为布局与风格方向，示例帖子、头像、数字和草稿状态不作为真实数据，也不会直接发布到生产。

使用内置 imagegen 生成，统一提示约束为：NanoCamp 现有浅紫纸色、蓝绿强调、无衬线标题、全站胶囊导航、独立右上角账号入口；采用 GitHub Discussions/CSDN 信息层次；无管理页、通知、点赞、收藏与大型营销首屏。页面分别强调分类列表、主帖与回复、Markdown 编辑与预览。
