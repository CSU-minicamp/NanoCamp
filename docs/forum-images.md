# 帖子图片：MySQL 存储与后续迁移

## 当前行为

发起讨论的正文编辑器提供图片图标按钮，也接受粘贴、拖入图片。图片先上传，再以 Markdown 插入正文；预览、刷新恢复草稿及发布详情页均支持图片。发布后仍不可修改正文或图片，只能撤回帖子。本次仅开放帖子正文，评论不开放图片。

正文和发帖预览使用适合连续阅读的中文无衬线字体，桌面字号 22px，手机字号 19px；评论及回复预览分别为 20px、18px，行高均为字号的 1.85 倍。图片等比左对齐显示，连续的纯图片段落按可用宽度自动换行，文字段落保持原有位置。桌面图片最大宽度 560px、最大高度 360px，手机最大高度 320px，并受正文容器宽度限制；不拉伸、不裁切。点击图片或通过键盘激活图片按钮可放大查看，点击遮罩、图片、关闭按钮或按 Esc 关闭，并返回原有滚动位置。这些限制仅影响页面显示，不改变存储尺寸。排版参考 [GitHub Primer Markdown](https://github.com/primer/css/tree/main/src/markdown)，上传按钮采用 [Lucide Image](https://lucide.dev/icons/image)，许可保存在 `public/vendor/lucide-LICENSE.txt`。

支持静态 JPEG、PNG、WebP，单文件不超过 5 MiB，每帖最多 9 个图片标记。服务端根据实际解码结果校验格式，拒绝动态图片和超过 16,777,216 像素的文件，自动旋转，按原比例缩到最长边 1920 像素并转为 WebP，清除 EXIF 等元数据。每个账号每小时最多上传 20 次，已有论坛资料、封禁及禁言检查同样生效。

## 初始化与表结构

```powershell
npm run forum:migrate
```

迁移可重复执行，只增加表，不删除已有数据：

- `forum_images`：图片 UUID、上传者、所属帖子（草稿时为空）、存储驱动、存储键、类型、大小、尺寸、ETag、创建时间。
- `forum_image_blobs`：MySQL `MEDIUMBLOB` 二进制内容，以存储键关联。

先写入新对象，再在同一个业务事务中写入图片元信息及幂等结果。失败时尝试删除新对象，清理失败会记录 `[forum:image:cleanup]` 日志。发布帖子时锁定图片记录并验证归属、草稿状态和时效，帖子及绑定一起提交；不能用他人的图片、已绑定其他帖子的图片、过期图片或外链图片发布。

## 接口

`POST /api/forum/images` 接收原始图片字节，不是 multipart 或 Base64 JSON。

请求需要登录会话、同源 Origin、`x-nc-csrf`、`Idempotency-Key`（8–80 个字母、数字、下划线或短横线），`Content-Type` 为实际的 JPEG/PNG/WebP 类型。相同账号和幂等键重试相同内容返回同一图片；不同内容复用键返回 409。

成功返回 201：

```json
{
  "id": "图片 UUID",
  "url": "/api/forum/images/图片UUID",
  "contentType": "image/webp",
  "size": 12345,
  "width": 1280,
  "height": 720
}
```

正文使用 `![图片](/api/forum/images/图片UUID)`。最多 9 个标记，包括对同一图片的重复引用；代码块中的示例不会绑定图片。发布接口会重新校验图片归属，不依赖客户端给出的图片列表。

`GET/HEAD /api/forum/images/:uuid` 通过记录上的驱动读取二进制，返回 WebP、尺寸对应的内容长度、ETag 和 `nosniff`。使用 `private, no-store`，每次请求重新检查可见性；ETag 条件请求也先检查权限。

- 尚未发布且不满 7 天：仅上传者会话可读取，用于预览和恢复草稿。
- 已绑定公开帖子：允许匿名读取。
- 帖子隐藏、撤回：任何人读取原图地址均返回 404。已经下载或显示的副本无法远程收回。
- 不存在、其他人的草稿、超过 7 天的未发布图片：404。

主要错误：401 未登录，403 CSRF/资料/参与限制，413 超过大小，415 类型不支持，422 图片损坏、像素超限、非法引用或超量，429 上传频率超限。失败不会清空正文草稿。

## 未发布图片清理

```powershell
npm run forum:images:cleanup
# 单批最多处理 1000 条，默认 100 条：
npm run forum:images:cleanup -- 500
```

命令只删除超过 7 天且未绑定帖子的图片，不删除已发布或撤回帖子的图片。需要在部署环境的定时任务中安排运行；当前没有自动配置操作系统任务。删除采用适配器的幂等 `delete`，失败退出并保留日志，可再次运行。

## 迁移到对象存储

`backend/forum-image-storage.mjs` 定义 `put({key,bytes,contentType})`、`get(key) -> Buffer | null`、`delete(key)` 三个方法，通过 `registerForumImageStore(name, adapter)` 注册新驱动。

注册后，在本地部署配置中设置 `forumImageStorage.driver`，新上传使用该驱动，旧记录继续使用自身的 `storage_driver`；不要将桶地址或对象存储键写入帖子正文。

历史迁移建议逐批执行：读取旧对象，复制并校验大小与散列，再条件更新该图片记录的驱动和键。UUID 及站内 URL 保持不变。保留旧对象一段时间供在途读取及回滚使用，验证后再清理；不能先删 MySQL 内容再切引用。当前已提供适配接口并验证混合读取，尚未绑定任何具体云厂商，也未执行线上迁移。

数据库及对象存储需一起备份；`forum_image_blobs` 中的二进制不能仅靠图片元信息恢复。

## 验证

`npm run forum:test` 包含图片格式/解码、MySQL 二进制一致性、缩放及元数据清理、权限隔离、绑定、幂等、限流、隐藏/恢复/撤回、过期清理及混合存储适配器测试。
