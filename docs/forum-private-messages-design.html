1 · 需求与设计边界

将用户明确要求、源码现状和本方案建议分开，避免把建议当成已经批准的结论。

已明确的要求

  • 新增私信功能，完成从入口到实际聊天、接收与返回的完整流程。
  • 把个人中心中的“消息”迁到论坛左侧 tab 导航，承接私信及现有通知。
  • 参考成熟论坛网站，交付设计方案；本次已实施对应业务代码。
本次实施范围。首期采用一对一文字聊天、陌生人消息请求与短轮询。群聊、附件、撤回、输入中提示和对方已读回执不纳入首期；用户已授权按本方案实施。

当前源码已确认：消息页为 /forum/notifications/，使用个人中心侧栏；论坛侧栏没有消息入口。现有消息是回复、关注、点赞和系统通知，不包含私信会话。右上角头像实际跳到消息页，forum-nav.js 每 60 秒读取一次未读通知。

迁移后：论坛侧栏新增“消息”；消息页保留同一论坛侧栏并高亮“消息”。个人中心移除独立消息 tab；右上角头像回到现有资料页 /forum/me/?tab=profile。头像上保留总未读角标，在站外页面仍能发现新消息；个人中心的“社区论坛”入口回到论坛后，可在左侧进入消息。

2 · 成熟产品参考

借鉴可验证的入口、会话和陌生人处理方式；具体实现是结合 NanoCamp 的建议。

来源已核实的产品行为本方案采用方式
Discourse 官方：侧栏使用说明侧栏提供 Chat 和 Direct Messages，并支持从侧栏发起新私信。把消息作为论坛常驻入口；消息页内提供“发私信”。
Discourse 官方：Chat即时短对话与论坛话题、通知协同。私信与论坛通知同属消息中心，但正文、会话状态与通知存储分开。
Reddit 官方：Chat 使用说明区分聊天与请求，允许接受或忽略请求；隐藏聊天后，后续新消息可使其重新出现。非互关用户先发一条请求；支持接受、忽略、屏蔽；移除会话只影响自己。

参考核查日期：2026-10-23。不会照搬外站的群聊、频道或复杂社交层级；以下业务规则和技术选型属于本项目设计。

3 · 入口、页面与布局

每一个入口都有明确落点、返回路径及未登录行为。

入口行为与落点
论坛左侧“消息”置于论坛侧栏最下方；保留其余导航顺序。显示消息总未读数，进入 /forum/messages/，默认展示私信。未登录则跳登录，登录后回到原目标。
消息中心内部导航私信、互动通知与系统通知保留独立路由，顶部分类导航行按最新要求移除。私信中再分“会话 / 消息请求”，入口显示各自未读；现有回复归入互动通知，保留回复、赞、关注筛选。
帖子详情作者区、公开个人主页对其他用户显示“发私信”；自己的主页不显示。点击打开与该用户的既有会话或新会话草稿。
评论作者昵称、头像沿用进入公开主页的行为，由主页“发私信”继续；不让点击头像同时承担聊天和资料两种动作。
消息中心“发私信”输入昵称搜索成员，展示头像、昵称及公开个人页链接。同名用户可先查看主页确认；不展示邮箱，不允许给自己发。
旧消息地址/forum/notifications/ 根据旧 filter 参数跳转到新中心的互动或系统页，保留通知详情跳转与旧链接可访问性。

桌面使用“论坛侧栏 + 会话列表 + 当前聊天”布局；沿用现有字体、浅色背景、边框与悬停风格，正文建议 18px。中小屏切成“消息列表 → 独立聊天视图”，顶部提供返回按钮、对方昵称及更多菜单；返回恢复列表滚动位置。手机键盘弹出时输入区贴合可视视口，聊天列表单独滚动，不压住最后一条消息。

首次无会话展示“暂无私信”和“发私信”；未选会话时提示选择或发起对话，不自动标记第一条为已读。会话列表每批 20 条，只展示头像、昵称、最后一条摘要、时间、本人未读和发送失败状态。

4 · 从发起到持续聊天的业务闭环

先定义双方看到什么，再定义会话状态如何变化。

步骤发送方 A接收方 B / 系统
1. 进入从作者区、主页或消息中心选择 B；立即进入聊天草稿。只打开草稿不创建数据库会话，不向 B 生成空会话或通知。
2. 首次发送输入 1–2000 个 Unicode 字符，发送时按钮防连点。前端显示“发送中”。校验会话成员、资料、禁言、屏蔽、长度和限流；第一条消息与会话一起提交。
3. 分流互相关注可直接聊天；否则仅能发一条首消息，展示“等待对方回应后可继续发送”。互关进入会话；其他情况进入“消息请求”，显示第一条内容、对方资料和接受 / 忽略 / 屏蔽 / 举报。
4. 接受或回应收到接受后解除发送限制；同一对用户始终回到同一会话。点击接受后转为正常会话；直接回复也可在同一事务内完成接受和发送。双方同时发起时，后到的一方发送视作回应，原子转为 active。
5. 忽略不暴露“已忽略”，仍只能看到等待回应状态，不可追加骚扰消息。忽略后请求从默认列表移除并清除请求未读；B 可从 A 的主页进入同一会话，主动接受或回复恢复。
6. 连续聊天自己的消息靠右，对方靠左；显示时间。发送成功才清空对应草稿。Enter 发送，Shift+Enter 换行；输入法选词回车不发送。前台查看聊天时增量接收；在底部才跟随滚动。正在阅读历史时显示“有新消息”，点击后滚到底部。
7. 失败与重试失败消息保留原文并提供重试；同一条重试沿用 request key。切换对话保留未发送草稿。超时后重试不会生成重复消息；明确成功以服务端提交结果为准，不能把本地气泡当作已经送达。
8. 离开与回来返回会话列表保留滚动与未读；刷新或重新登录后会话及历史仍在。数据库持久化；首批只读最近 30 条，向上读取历史，禁止首次全量加载。
9. 移除或屏蔽“移除会话”仅隐藏自己的列表项，不删除对方消息或双方历史。后续有效新消息恢复隐藏会话；屏蔽后禁止双方继续发送，不影响查看既有历史；解除屏蔽须显式操作。

建议限流默认值：正常会话每用户每分钟最多 20 条；陌生人每天最多新建 5 个请求；每个待回应会话仅 1 条。参数可配置，超限返回明确等待时间。既有账号禁言限制发送和接受动作，仍可阅读、忽略、屏蔽、举报与标记已读。

5 · 未读、通知与历史迁移

统一消息入口，但避免一条私信重复产生两次红点。

对象统计与操作规则
总角标私信未读消息条数 + 未查看请求数 + 互动未读事件数 + 系统未读事件数；私信正文不再额外写一条普通通知。同一类请求只计 1 次。显示上限 99+，服务端仍返回真实值。
会话未读仅统计他人发送且序号大于本人 last_read_seq 的消息。只有页面前台可见且对应消息进入聊天可视区域后才提交已读游标；请求预览不会自动接受。
读历史已读游标只前进不倒退；停留历史位置时不把下方未见新消息标为已读。多标签页和多设备读取服务端状态，恢复前台立即同步。
全部已读互动和系统页分别提供“全部标为已读”；不能顺带消除未打开私信。首期私信只按具体会话可见内容更新游标。
轮询活跃聊天每 2 秒拉取新增；会话列表前台每 5 秒刷新首批与未读；非消息页沿用每 60 秒同步总角标。后台标签页停止轮询，回到前台立即补拉。
原通知保留现有 forum_notifications 数据和已读状态。reply / like / follow 进入互动页，举报结果和内容处理进入系统页；不复制一份新数据。
通知点击继续校验权限和原内容状态；可见则跳对应帖子 / 回复 / 用户页。内容撤回或隐藏时展示现有占位，不从旧通知泄漏原文。

轮询刷新列表时保留当前会话、输入内容和历史滚动位置；发送或标已读成功后立即本地更新，再向服务器校准。网络失败使用 2、4、8、15 秒退避并显示可重试状态；非消息页沿用 60 秒间隔意味着全站角标并非即时到达。

6 · 权限、屏蔽与举报闭环

私信默认仅双方可见，举报只向有授权的运营人员开放必要证据。

  • 所有会话、消息、摘要、未读、已读和举报 API 都验证当前登录用户身份与会话成员资格；无法通过猜测 ID 读取他人消息。无访问权统一返回 404。
  • 与自己聊天禁止；已注销或不可用账号不能建立新会话；资料不完整跳到现有完善资料流程并保留目标，禁言账号保留只读及防骚扰操作。
  • 正文首期按纯文本渲染，保留换行，不解析 HTML、图片或 Markdown。站内公共搜索、论坛搜索联想、站点地图和公开缓存不能出现私信正文或摘要；私有页面与 API 均 no-store。
  • 屏蔽关系以用户对持久化；任一方屏蔽后双方停止发送，请求也不能绕过。解除仅能移除自己设置的屏蔽；对方仍屏蔽时继续不可发送。对被屏蔽方统一提示“暂时无法向该用户发送消息”，不透露对方具体设置。
  • 消息菜单提供举报；接收者可以举报收到的消息，选择现有原因并补充说明，提交后进入“我的举报”中的私信分类。用户不能举报自己发送的内容。
  • 私信举报独立建表：现有 forum_reports 强制 topic_id 且只接受 topic / reply，不能直接塞入私信。运营队列需新增私信类型、领取、裁决与审计入口，沿用现有受控命令行运营方式，首期不新建管理后台。
  • 仅授权审核者领取举报后可读取被举报消息和前后各最多 5 条证据；每次访问审计。确认成立可隐藏违规消息并限制该账号发言；驳回保留内容；误判可经审计恢复。双方历史中的隐藏内容变为占位，不自动删除整段对话。
  • 举报人可在处理开始前撤回；结案结果通过系统通知返回举报人，处理内容的通知返回作者。结果只含必要处理结论，举报人身份不向被举报方公开。
这里的“私信”是访问权限隔离，不是端到端加密。方案不宣称管理员完全无法查看；运营访问仅围绕举报证据并留审计。首期不设置自动清理历史，移除会话也不等于销毁数据。

7 · 技术架构与数据模型

扩展现有 Node.js + MySQL，不引入独立聊天服务或消息队列。以下命名均为新增契约。

新增数据表核心字段、唯一约束与职责
forum_dm_conversationsid；user_low / user_high（用户 ID 排序后唯一用户对）；initiator_id；state=pending/active；request_state=pending/ignored；last_seq；last_message_at。UNIQUE(user_low,user_high)。不存前端草稿。
forum_dm_membersconversation_id + user_id 复合主键；last_read_seq；hidden_through_seq。用户会话列表索引(user_id, conversation_id)。每会话必须且仅有双方成员。
forum_dm_messagesid；conversation_id；seq；sender_id；client_message_id；body；status=published/hidden；created_at。UNIQUE(conversation_id,seq)、UNIQUE(sender_id,client_message_id)，索引(conversation_id,seq)。
forum_user_blocksblocker_id + blocked_id 唯一；created_at。只影响私信发送，不顺带修改公开帖、关注或既有历史。
forum_dm_reportsid；reporter_id；conversation_id；message_id；reason；details；status；assigned_to；resolution；version；created_at / updated_at。开放举报去重，生命周期与现有举报一致。
复用表users / sessions / forum_members：账号、会话与禁言；forum_follows：判断互关；forum_write_requests：幂等模式；forum_audit：审核与证据访问审计；forum_notifications：原通知和私信举报结果。
发送事务（伪代码）
1. 读取会话，验证发送者是成员；按现有规则锁定发送用户并校验资格。
2. 按唯一用户对建立或定位会话；锁住 conversation 行，重新检查会话状态与双向屏蔽。
3. 检查同一 client_message_id；重复请求返回原消息，内容不同则 409。
4. 新会话判断互关；pending 的发起方只能发第一条，接收方回复原子变为 active。
5. 在 conversation 行锁内分配 seq=last_seq+1，插入消息，更新 last_seq / last_message_at。
6. 提交后返回 server_message_id、seq、created_at；前端用同一 client_message_id 替换本地气泡。
7. 任一步失败整体回滚，不出现空会话或只有半边成员的记录。

会话发送与屏蔽操作需对同一 conversation 行加锁并统一锁顺序；提交前再次检查屏蔽，避免“校验通过后刚好被屏蔽”仍落入新消息。新用户对使用唯一键处理并发创建；两个方向同时首发也只能产生一个会话。

聊天按 seq 排序；游标 before_seq / after_seq 查询，每次最多 30 条，历史翻页前后保持视口锚点。已读更新采用 max(old,last_visible_seq)，验证游标属于本会话且不超过已存在的消息。列表按 last_message_at、id 排序，每批 20 条，按会话 ID 合并去重；顶端增量刷新捕获新近活跃会话。

8 · 页面与 API 契约

页面地址用于回跳与分享给本人；数据接口始终执行服务端成员鉴权。

页面地址（新增）用途
/forum/messages/私信会话列表，手机默认列表视图。
/forum/messages/?tab=activity / ?tab=system互动通知 / 系统通知；通知 filter 参数继续兼容。
/forum/messages/new/?to=用户ID既有会话则跳对应会话，否则显示首消息草稿；无 to 时选择成员。
/forum/messages/conversations/:id/完整聊天页；返回消息列表。
/forum/me/?tab=reports&kind=dm在现有“我的举报”内查看私信举报与处理结果。
方法与新增 API请求 / 行为
GET /api/forum/message-summary返回 dm_unread、request_unread、activity_unread、system_unread、total_unread；不返回私信正文。替代全站轮询完整通知列表。
GET /api/forum/dm/recipients?q=仅登录可用，最多 10 个公开成员；昵称、头像、公开主页，不暴露邮箱。
GET /api/forum/dm/conversations?filter=active|requests&cursor=每批最多 20；只返回本人会话及必要摘要；读取请求不等于接受。
POST /api/forum/dm/conversationsto_user_id、body、client_message_id；原子创建会话并发首消息，已存在则在既有会话按当前规则发送。
GET /api/forum/dm/conversations/:id/messages?before_seq=|after_seq=两个游标互斥；无游标返回最近 30 条；返回 has_more、next_cursor、成员状态、本人 read_seq。
POST /api/forum/dm/conversations/:id/messagesbody、client_message_id；成功返回消息 ID、seq、server time；失败不清空输入。
POST /api/forum/dm/conversations/:id/accept 或 /ignore仅请求接收者可操作；重复提交幂等。ignore 清除请求未读并隐藏默认请求项。
POST /api/forum/dm/conversations/:id/readlast_visible_seq；单调更新自己的游标，不修改对方记录，不把接受状态一并改变。
POST /api/forum/dm/conversations/:id/hide只改变本人隐藏水位；新消息恢复列表可见。
POST /api/forum/dm/users/:id/block 或 /unblock设定或移除本人屏蔽，返回当前会话可发送性；不取消对方屏蔽。
POST /api/forum/dm/reports；POST /api/forum/dm/reports/:id/withdrawmessage_id、reason、details；仅收到消息的一方可举报；处理开始前可撤回。列表并入现有个人举报查询的 kind=dm。

复用 nc_sid、nc_csrf、same-origin、JSON 与 Idempotency-Key 规范。GET 只读；发送、接受、忽略、隐藏、屏蔽、已读、举报均走 POST。无权读取统一 404；未登录 401；资料不全或禁言 403；等待对方回应或不可发送 409；长度非法 422；超限 429 + retry_after；服务不可用 503。

新增系统通知 kind=dm_report_result / dm_content_hidden / dm_content_restored，target_type=dm_report；展示仅含处理结论并指向本人举报详情或授权会话。当前通知渲染白名单和接口需一同扩展，普通关注/点赞聚合不处理私信。

9 · 改造清单、上线顺序与降级

先把双方能稳定收发的链路打通，再开放入口；缺任一闭环不应视作功能完成。

顺序交付内容与门槛

10 · 验收用例

以下均是待实现后的验收要求，实现后按下列场景验收；具体测试结果见实施交付。

场景必须满足的结果
入口迁移论坛侧栏可进入消息；个人中心无重复消息 tab；头像回资料；旧通知链接仍可用；手机列表和聊天可往返。
陌生人首发A 首发后显示等待回应，B 在请求页收到 1 条；A 无法继续发第二条，B 接受或回复后双方可持续聊天。
互关与并发互关首发直接 active；A/B 同时首发只生成一个用户对会话和正确的两条消息，顺序唯一。
发送重试连点、超时后重试、页面重复请求均不重复入库；同 request key 不同内容明确冲突；失败原文可恢复。
历史和滚动500 条历史仍只首取 30 条；向上加载保持位置；看历史时新消息不强制滚动或自动已读。
未读隔离仅可见他人消息推进本人游标；后台标签页不清未读；请求只计一次；不重复写普通通知；多设备读游标不回退。
权限与泄漏第三方猜 ID 不能读正文、摘要、游标、举报证据；匿名不能搜索私信用户；全站搜索和论坛联想没有私信；公共缓存无私信内容。
输入与状态空白、超长、HTML、表情、换行、中文输入法 Enter、账号禁言、资料不全、注销和断网都符合约定。
忽略和隐藏忽略不泄露给 A；B 可从主页恢复回应；移除列表不删除历史，新消息可恢复；对方记录不受影响。
屏蔽竞争屏蔽与发送并发执行时遵守事务先后；屏蔽后不能另建会话绕过；只解除自己一侧屏蔽，历史仍可读。
举报处理仅接收者可举报收到的消息，去重、撤回、领取、裁决、隐藏、驳回、误判恢复、审计及双方结果通知形成闭环。
布局与降级1440 / 1024 / 390 / 360px，长昵称长消息不溢出，手机键盘不挡输入；轮询失败退避，恢复后补拉且不重复气泡。
